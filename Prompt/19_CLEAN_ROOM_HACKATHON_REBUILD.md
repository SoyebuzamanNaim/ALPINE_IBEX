# Clean-Room Hackathon Rebuild Guide

Purpose: convert pre-hackathon knowledge into a compliant competition build without misrepresenting prototype code.

## Before the hackathon
Keep prototype repository separate.

## At official start
Create a new repository.

## Rebuild order
1. requirements
2. schema
3. ingestion
4. one baseline model
5. retrieval
6. envelope guard
7. one counterfactual flow
8. one agent path
9. frontend
10. integration
11. validation
12. demo

## Reuse
Reuse:
- knowledge
- architecture decisions
- scientific findings
- dataset understanding
- documentation insights

Do not copy pre-hackathon implementation code into the submitted repository unless competition rules or Local Lead explicitly permit it.

Maintain a transparent development history.
